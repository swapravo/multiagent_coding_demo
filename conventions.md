# Project Conventions

This file defines the authoritative tech stack and coding conventions for this project.
All agents MUST read and adhere to these conventions before generating any plan or code.

---

## Tech Stack

| Layer       | Technology                         | Notes                                       |
|-------------|-------------------------------------|---------------------------------------------|
| Backend     | Python 3.11+ / FastAPI              | Use `async` endpoints, Pydantic v2 models   |
| Frontend    | Node.js / TypeScript + React (Vite) | Use functional components, React hooks only |
| Database    | SQLite3                             | Use raw SQL via `aiosqlite`; no heavy ORMs  |
| API Style   | REST (JSON)                         | OpenAPI docs auto-generated by FastAPI      |
| Auth        | JWT (Bearer token)                  | `python-jose` for signing/verification      |
| Env Config  | `.env` files via `python-dotenv`    | Never hardcode secrets                      |

## Backend Conventions (FastAPI)

- Use `APIRouter` to group routes; register routers in `main.py`
- Route files go in `backend/routers/`
- Pydantic schemas (request/response) go in `backend/schemas/`
- Database logic goes in `backend/db/`
- Use `aiosqlite` for async DB access
- All endpoints return consistent JSON: `{"data": ..., "error": null}`
- HTTP status codes: `200` for success, `201` for creation, `400` for bad input, `422` for validation errors, `500` for server errors

## Frontend Conventions (React + TypeScript + Vite)

- Component files: `PascalCase.tsx`
- Utility/hook files: `camelCase.ts`
- API calls go in `frontend/src/api/`
- State management: React Context + `useReducer` (no Redux unless explicitly needed)
- Styling: CSS Modules (`.module.css`) co-located with components
- No `any` types in TypeScript -- always define proper interfaces

## Database Conventions (SQLite3)

- Schema definitions in `data_model/schema.sql`
- Migration scripts in `data_model/migrations/`
- Use `INTEGER PRIMARY KEY AUTOINCREMENT` for all primary keys
- All tables have `created_at` and `updated_at` TIMESTAMP columns
- Foreign keys must be explicitly enabled: `PRAGMA foreign_keys = ON;`

## Naming Conventions

- Python: `snake_case` for variables/functions, `PascalCase` for classes
- TypeScript: `camelCase` for variables/functions, `PascalCase` for components/interfaces
- SQL tables: `snake_case` plural (e.g., `user_profiles`, `order_items`)
- SQL columns: `snake_case`
- Environment variables: `SCREAMING_SNAKE_CASE`

## File Header Convention

Every generated source file must start with:
```
# Generated by: <agent_name>
# Date: <ISO date>
# Plan reference: output/plan/<agent>_plan.md
```

---

## Inter-Agent Communication

Agents communicate via the shared `output/plan/` directory.
Each agent MUST:
1. Read all previously written plan files before generating its own plan
2. Respect decisions made by upstream agents (do not contradict them)
3. Reference upstream plan files explicitly in its own plan

Pipeline order (strict):
1. `requirements_collection_agent`
2. `data_modelling_agent`
3. `backend_agent`
4. `frontend_agent`
